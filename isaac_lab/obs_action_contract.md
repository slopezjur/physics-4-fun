# Observation / action contract — Isaac Lab ⇄ Godot

**Status: frozen.** Changing anything on this page invalidates every checkpoint trained against
it. That is not a stylistic warning — it is the failure this project has already paid for once,
in commits `31573c2 → 94402ad → ebbaa1b`, where an observation width drifted between the trainer
and the engine and surfaced as an ONNX shape crash at load rather than as a diff.

Both sides implement this document. Neither side is the source of truth for the other; this file
is. The machine-readable half lives in `assets/dummy_rig.json`, generated by
`tools/tscn_to_urdf.py` from `Scenes/ActiveRagdoll.tscn`.

---

## 1. Control rate

| | Isaac Lab | Godot |
|---|---|---|
| Physics | 120 Hz (`sim.dt = 1/120`) | 120 Hz (`physics_ticks_per_second`) |
| Policy | 60 Hz (`decimation = 2`) | 60 Hz (**`action_repeat = 2`**) |

**Godot currently ships `action_repeat = 8`, which is 15 Hz.** That must change to `2` in all four
RL scenes before a policy trained here will work there:

- `Scenes/RL/Upright/RagdollStandTraining.tscn`
- `Scenes/RL/Upright/RagdollGetUpArena.tscn`
- `Scenes/RL/Locomotion/RagdollWalkArena.tscn`
- `Scenes/RL/Locomotion/RagdollWalkTraining.tscn`

This is a hard requirement, not a preference. A policy trained at 60 Hz and replayed at 15 Hz
receives every observation four times too late and holds every action four times too long; it will
not merely degrade, it will fall over.

## 2. Action vector — 36 floats

Order is `dummy_rig.json → actuated_joints`, which is
`RagdollRLBridge.ControlledBoneNames` × `(x, y, z)`:

```
index 3*i + 0  ->  <bone_i>_rx     (Godot local X, lateral / pitch)
index 3*i + 1  ->  <bone_i>_ry     (Godot local Y, vertical / yaw)
index 3*i + 2  ->  <bone_i>_rz     (Godot local Z, forward / roll)
```

with bones in order:

```
0 Spine        1 Chest
2 UpperArm_L   3 Forearm_L    4 UpperArm_R   5 Forearm_R
6 Thigh_L      7 Shin_L       8 Foot_L
9 Thigh_R     10 Shin_R      11 Foot_R
```

Each value is in `[-1, 1]` and maps onto that specific axis's own limit as an absolute target,
**piecewise-linear about the rest pose**:

```
ACTION_SCALE = 0.4

a      = clamp(policy_output, -1, +1)          # MANDATORY - see below
span   = (upper - default)  if a >= 0  else  (default - lower)
target = default + ACTION_SCALE * a * span
```

**The clamp is not optional and is not defensive politeness.** The network's output is an unbounded
Gaussian mean; nothing in the architecture keeps it inside `[-1, 1]`. A Stand policy trained
without a barrier term reached raw outputs of +/-18, with 97% of components past the boundary - fed
unclamped into the mapping above, that commands joint targets roughly 15x their intended
deflection, which is not a degraded gait but an immediate explosion. The training environment
clamps, so the policy is *defined* by its clamped output; Godot must apply the same clamp to see
the same behaviour.

`default` is 0 for every joint (the Godot rest pose), and `a = 0` is therefore the rest pose. The
two halves have different slopes because the limits are asymmetric — that is intended, not an
approximation.

**`ACTION_SCALE = 0.4` is part of the contract, not a tuning knob.** Godot must apply the same
factor; omitting it makes every commanded motion 2.5× too large. It exists because mapping the
full `[-1, 1]` onto a joint's whole range is too coarse to balance with: the knee spans 2.7 rad,
so `a = 0.5` would command a 1.35 rad swing, and against that joint's 1600 Nm/rad stiffness the
actuator simply pins at its effort limit — the action space degenerates to bang-bang. Measured at
scale 1.0, the policy plateaued at 48-step episodes while a zero-action policy from the same pose
survives 168; acting was worse than doing nothing. The far end of each joint's range is still
reachable, just over several steps rather than one.

> **This differs from `JointLimitedActionSpace`, and Godot must be changed to match.** That class
> maps affinely across the whole range, `target = lower + (a+1)/2 * (upper - lower)`, which puts
> `a = 0` at the *midpoint of the limits* rather than at the rest pose. For the knee (`[-2.6, 0.1]`)
> the midpoint is −1.25 rad, so a freshly initialised policy — which outputs approximately zero —
> commands a deep crouch from the first step. Measured in Isaac before the change: mean episode
> length 22 steps out of 480, a 0.37 s collapse, on every episode. The property that motivated
> per-axis scaling in the first place is preserved exactly (the full `[-1, 1]` maps onto the
> reachable range of that axis, nothing wasted past a hard stop); only the zero point moves.

`lower`/`upper` per joint are in `dummy_rig.json`. They are the Godot limits, so Godot should use
its own live joint limits and get the same numbers; if the two disagree, the scene changed and the
URDF was not regenerated.

`Head`, `Hand_L` and `Hand_R` (9 DOF) are **not** in the action vector. They are actuated in both
engines by a PD drive holding a constant zero target, matching what Godot already does — they have
real gains in the scene but were never commanded by RL.

### Axis sign — the one place a silent error hides

Isaac is Z-up, Godot is Y-up. Positions map `urdf = (-godot.z, godot.x, godot.y)`. For rotations:

| Godot axis | URDF axis | Sense |
|---|---|---|
| X (lateral, pitch) | Y | same |
| Y (vertical, yaw) | Z | same |
| Z (forward, roll) | X | **reversed** — limits negated and swapped |

The converter asserts the shoulder and hip roll limits stay mirror-symmetric across L/R after
conversion, because that asymmetry is the only property in the rig that catches a sign slip.
**Godot does not need to apply this mapping to actions** — it commands its own local axes directly,
and the mapping was already applied when the URDF was built.

## 3. Observation vector — 143 floats

| Slice | Width | Contents |
|---|---|---|
| `[0:3]` | 3 | Projected gravity in the pelvis frame. Upright ⇒ `(0, 0, -1)`. |
| `[3:6]` | 3 | Root linear velocity, yaw-frame (heading-relative), m/s |
| `[6:9]` | 3 | Root angular velocity, pelvis frame, rad/s |
| `[9:10]` | 1 | Pelvis height above ground, m (rest = 0.82) |
| `[10:55]` | 45 | Joint position − default, rad, **all 45 DOF** in `dummy_rig.json → joints` order |
| `[55:100]` | 45 | Joint velocity, rad/s, same order |
| `[100:104]` | 4 | Contact flags: `Hand_L, Hand_R, Foot_L, Foot_R` — 1.0 if ‖force‖ > 1 N |
| `[104:140]` | 36 | Previous action, as sent (pre-scaling, in `[-1, 1]`) |
| `[140:143]` | 3 | Velocity command `(vx, vy, yaw_rate)` — **all zero for Stand** |

The final three slots are a **reserved velocity command**, held at zero for Stand. They are dead
weight for this task and exist anyway, because Walk is bootstrapped from a Stand checkpoint and
that only works while the widths match. A command has to reach the input layer for "go that way"
to mean anything to a trained network, so the slots must exist before walking uses them — adding
them later orphans every Stand checkpoint. This is the same argument `BodyStateObservation` makes
for its reserved 7-float joystick block, applied to this layout.

Note this is **not** the Godot 113-dim `BodyStateObservation` layout. That width is frozen for
reasons internal to the Godot lineage (checkpoint compatibility, the reserved 7-float joystick
block) and carries root-relative bone quaternions rather than joint angles — a representation that
does not exist in a reduced-coordinate articulation, where joint angle *is* the state. Godot must
therefore implement this layout to consume the policy. All of it is available on the Godot side;
joint angles come from the same `GetJointAngularLimits` / bone-local decomposition the action path
already uses in reverse.

Velocities and gravity are expressed in **Godot's own axes**, not Isaac's — the policy was trained
on quantities computed in the pelvis frame, and that frame is whatever the engine calls it. The
only thing that must match is *which physical quantity* sits in each slot.

## 4. ONNX interface

Exported by `scripts/play.py` via rsl_rl's `export_policy_as_onnx` to
`logs/rsl_rl/p4f_stand/<run>/exported/policy.onnx`.

| | |
|---|---|
| Input | `obs`, `float32[1, 143]` |
| Output | `actions`, `float32[1, 36]` |

**Observation normalization is baked into the graph** (`actor_obs_normalization = True`). Godot
feeds raw observations and must not normalize them itself. There are no separate mean/std files to
ship, and no hidden state — the policy is a feed-forward MLP, so no `h_in`/`c_in`.

Verified against a real export (150-iteration checkpoint, 950 KB): `onnx.checker` passes, the
graph reports `obs [1, 143] -> actions [1, 36]`, and a rest-pose observation returns finite
commands in `[-0.23, 0.19]` concentrated on the hip and shoulder — small corrections about the
neutral pose, which is what the action mapping in §2 predicts.

Note `play.py --checkpoint` takes a **full path**, not a filename; a bare `model_149.pt` fails with
`Unable to find the file`. Use `--load_run <dir>` to take that run's latest instead.

The output is the distribution **mean**, not a sample: deterministic at inference, which is what
you want in-engine.
